# Offline translation subsystem

The translator runs a small Python worker as a Windows `--onedir` executable. It accepts UTF-8 JSON Lines on stdin and returns JSON Lines with the same request `id` on stdout; diagnostics go to stderr. The C# client starts the worker on the first translation, allows up to eight outstanding requests, times each request out after three minutes, and reads at most 8 Mi characters per response line. A timed-out or cancelled request invalidates that worker process generation so queued stale text cannot build up; the next request lazily starts a fresh worker. Responses are tied to their originating process and late replies are ignored. The worker exits after 90 idle seconds. Text is never written to logs.

Only the most recently used translation direction stays loaded in RAM. Switching direction releases the previous CTranslate2 translator before loading the other package; the on-disk model files remain installed. CTranslate2 is configured for CPU `int8`, one inter-op worker, and two intra-op threads. Before CTranslate2 is imported, the worker sets `OMP_WAIT_POLICY=PASSIVE` and `KMP_BLOCKTIME=0`. OpenMP documents PASSIVE as a hint for waiting threads to sleep/yield; Intel documents `KMP_BLOCKTIME` as the spin interval before sleeping. CTranslate2 recommends avoiding total intra/inter threads above available physical cores, and two intra threads limits idle thread/stack reservation for this interactive workload ([OpenMP wait policy](https://www.openmp.org/spec-html/5.0/openmpse55.html), [Intel runtime variables](https://www.intel.com/content/www/us/en/docs/dpcpp-cpp-compiler/developer-guide-reference/2025-0/supported-environment-variables.html), [CTranslate2 threading](https://opennmt.net/CTranslate2/parallel.html)).

One 30-second idle sample on the 28-logical-processor Windows host, after translating once in both directions and keeping stdin open, measured 212.16 MiB working set, 1,867.04 MiB private memory, and 0.000% CPU across all cores. The prior both-models-retained sample on the same host measured 431.44 MiB working set, 2,971.60 MiB private memory, and 0.11% CPU. This sample reduced working set by 50.8% and private memory by 37.2%; memory remains substantial and these are measurements from one machine/run, not a guarantee. The measurement used `tools/measure-worker.ps1` and `artifacts/ui-smoke-accepted/isolated-data/models`.

The two models are Argos Translate 1.9 packages, listed in the [official Argos package index](https://raw.githubusercontent.com/argosopentech/argospm-index/main/index.json). Argos packages contain a CTranslate2 `model/` directory plus their tokenizer model; these archives also contain Stanza tokenization data which is not needed by this worker. This package layout and model runtime are documented by [Argos](https://github.com/argosopentech/argos-translate/blob/master/argostranslate/package.py) and [CTranslate2's Marian guide](https://opennmt.net/CTranslate2/guides/marian.html). The actual SentencePiece processor is kept with each package and loaded through [SentencePiece](https://github.com/google/sentencepiece).

`ModelInstaller.Models` is the pinned manifest. Download is an explicit UI action; import accepts only a package whose exact size and SHA-256 match this manifest. Extraction validates ZIP names, rejects traversal and symlinks, limits archive entries and expanded size, validates package direction/version, writes to a staging folder, and swaps the installed directory atomically. Only `model/`, `sentencepiece.model`, metadata, and README are installed. The source archives also contain Stanza `.pt` tokenization data; that content is deliberately not installed or loaded. SentencePiece is the actual tokenizer declared by each package.

The package index records Argos model version and download URLs; `metadata.json` itself does not declare a license. Package README files credit upstream corpus/model sources but do not provide a clear package-wide license grant. This implementation therefore does not claim that the translation model licenses have been independently verified. Review the upstream terms before redistributing model packages. The source index and model packages remain separate from the application installer; this repository keeps locally downloaded validation archives under ignored `artifacts/model-cache/` only.

## Worker build and offline validation

Use Python 3.12 on Windows. The dependency lock fixes exact versions and hashes for CTranslate2, SentencePiece, PyInstaller, and their transitive packages. Build the worker with:

```powershell
./tools/build-worker.ps1
```

The output is `artifacts/worker/cyclop-translator/cyclop-translator.exe` plus its onedir runtime files. `worker/test_worker.py` validates both pinned archive SHA-256 values, extracts only the required model files in a temporary directory, and runs actual CPU translations in both directions including paragraphs and long input. Pass the frozen executable path to that script to test the packaged worker:

```powershell
worker/.venv/Scripts/python.exe worker/test_worker.py artifacts/worker/cyclop-translator/cyclop-translator.exe
```

At process start, a non-removable CPython audit hook denies every `socket.*` event, including socket creation, DNS resolution, bind, and connect. These are CPython audit events documented in the [official audit event table](https://docs.python.org/3/library/audit_events.html). The frozen smoke check attempts all three (with connect rejected before reaching Winsock) and verifies denial. This is Python socket API enforcement; Windows firewall policy is not changed, OS-level network isolation, native code bypass, network adapter state, and post-reboot conditions were not tested.

After the model install/download action finishes, translation itself uses only local files. No server, HTTP listener, cloud fallback, PyTorch, or CUDA runtime is used. CTranslate2 uses CPU `int8` when reported by the installed runtime and `int8_float32` otherwise. The CTranslate2 Windows wheel also carries an optional `cudnn64_9.dll`; the build script removes every nested cuDNN copy from the onedir output. The rebuilt package was scanned recursively and contains none. CTranslate2's PE import table has no cuDNN imports, and the frozen CPU worker passed real translations with cuDNN removed. PyInstaller's onedir package includes `python312.dll`, CTranslate2/SentencePiece native extensions, Intel OpenMP, and the required MSVC runtime DLLs (`MSVCP140.dll`, `VCRUNTIME140.dll`, and `VCRUNTIME140_1.dll`). Sentence boundaries are estimated from punctuation, then unusually long sentences are split at a hard cap of 120 SentencePiece tokens per chunk; paragraph line breaks are retained. CTranslate2 decoding is bounded to 1,024 output tokens per chunk; if a hypothesis reaches the bound, the worker returns an explicit error and does not present the clipped text as complete. Splits can still lose long-range context.
